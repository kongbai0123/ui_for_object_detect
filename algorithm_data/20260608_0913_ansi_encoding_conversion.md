# 決策記錄：批次檔編碼轉換為 ANSI (CP950)
**時間**：2026-06-08 09:13:00

---

## 1. 背景與問題診斷
從使用者提供的螢幕截圖中可以發現，即使在 `.bat` 中宣告了 `chcp 65001`，Windows 命令提示字元仍會在一開始載入檔案時以預設的 Code Page 950 (Big5) 解析，導致：
1. 第一行 `@echo off` 的 UTF-8 前導字元 (BOM) 被解讀為亂碼。
2. 檔案中的中文提示字元亂碼被 cmd 誤判為指令（如 `'繳勖?剷刻...'`）。
3. 原本的英文指令 `start` 被截斷或誤判，甚至引號字串 `'"YOLO UI Backend"'` 被當作指令執行。

---

## 2. 解決方案

### 決策：將 `start_yolo_ui.bat` 的編碼轉為 ANSI (CP950 / Big5)
*   **理由**：Windows cmd.exe 最相容的編碼格式為系統預設的 ANSI (繁體中文 Windows 為 CP950)。將批次檔改為 ANSI 編碼可以免除一切 `chcp` 設定，中文字能直接正確顯示，且語法解析絕對不會出錯。
*   **實作方法**：
    我們將以 Python 腳本讀取當前 UTF-8 格式的批次檔，移除 `chcp 65001 >nul`，然後將其轉存為 `cp950` (ANSI) 編碼寫回檔案。
