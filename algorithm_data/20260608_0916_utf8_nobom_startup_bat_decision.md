# 決策記錄：使用無 BOM UTF-8 編碼與啟用字碼頁 65001
**時間**：2026-06-08 09:16:00

---

## 1. 背景與使用者回饋
使用者指出，雙擊批次檔 `start_yolo_ui.bat` 能正常運行，但在編輯器中查看時發現中文字元出現了亂碼（因檔案為 ANSI/CP950 編碼，而現代編輯器如 VS Code 預設使用 UTF-8 讀取）。

---

## 2. 解決方案

### 決策：使用「無 BOM 的 UTF-8 (UTF-8 without BOM)」儲存批次檔，並在第一行執行 `chcp 65001`
*   **理由**：
    1.  **編輯器相容性**：以無 BOM 的 UTF-8 儲存，可確保在任何現代編輯器（VS Code、Sublime Text、Notepad++ 等）中開啟時，中文都能完美顯示，不會有亂碼。
    2.  **Windows 執行相容性**：我們在批次檔開頭的前兩行設定：
        ```cmd
        @echo off
        chcp 65001 >nul
        ```
        且確保寫入時**不包含 BOM (Byte Order Mark)**。沒有 BOM 能避開 cmd 在解析第一行指令時的解析錯誤；`chcp 65001` 則會強制將 CMD 視窗切換為 UTF-8，使之後的所有中文輸出及英文指令都能完美被執行。
*   **實作方法**：
    使用 Python 以 `utf-8` 編碼寫入檔案，確保無 BOM，並使用 `/` 正斜線以避開 Python 的斜線轉義問題。
