# 決策記錄：修復啟動批次檔編碼亂碼問題
**時間**：2026-06-08 09:10:00

---

## 1. 背景與問題診斷
使用者在執行 `start_yolo_ui.bat` 時出現以下錯誤：
- `'art' 不是內部或外部命令...` (原本是 `start`)
- `'?echo' 不是內部或外部命令...` (原本是 `@echo off`)

**原因分析**：
Windows 預設指令提示字元 (cmd.exe) 使用 Code Page 950 (Big5) 解碼，而批次檔以 UTF-8 格式儲存。這導致：
1. 檔案開頭的 UTF-8 BOM 被誤判為特殊字元，使 `@echo off` 變成 `?echo off`。
2. 批次檔中的中文註解 (如 `:: 正在背景啟動`) 產生亂碼，截斷了後續的 `start` 命令為 `art`。

---

## 2. 解決方案

我們採取以下修正措施，以確保 100% 的相容性與無亂碼執行：
1.  **切換字碼頁**：在批次檔開頭第一行加上 `chcp 65001 >nul`，強制命令提示字元切換為 UTF-8 編碼。
2.  **避免中文字元干擾語法**：將註解改為英文，移除容易在解碼錯誤時破壞語法的 `::` 註解。
3.  **編碼一致性**：維持寫入為無 BOM UTF-8 編碼，配合 `chcp 65001` 即可完美顯示中文提示。
